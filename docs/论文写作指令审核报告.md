# 论文写作指令审核报告

**审核对象**：用户上传 PDF《论文写作与返修总指令 V4.1（精简版）》（18 页图片稿，无文本层）。  
**对照上下文**：仓库 `/workspace` 仅有占位 `README.md`，无既有论文草稿或写作规范，故以 PDF 为唯一原稿，本报告与升级指令为新建成果。  
**升级成果**：[`论文写作与返修总指令-V5.0-期刊发表版.md`](./论文写作与返修总指令-V5.0-期刊发表版.md)  
**审核尺度**：SCI / SSCI / EI / 中文核心等正规期刊的可投稿性（IMRaD、问题与贡献、方法可复现、结果—讨论分离、文献批判性、图表、语体、伦理、引用、可检验主张）。

本报告区分三类表述：

- **原稿要求**：PDF 中确有的规定。
- **缺陷**：原稿已有但不足以支撑正规期刊、或与通行审稿规范冲突。
- **本版新增**：V5.0 为达期刊标准而补入，不是作者“原来就要求”。

---

## 1. 原稿在做什么（先还原意图，避免误改）

V4.1 是一份 **给代写/主控作者用的总控指令**，不是某一篇已完成论文的大纲。其明确意图包括：

1. 服务 **中文学术期刊、职称论文、行业实践研究**。
2. 用门禁（Gate）和状态机约束写作过程，核心红线是 **不编造**。
3. 覆盖工程、教学、管理、实证、综述五类骨架。
4. 强调期刊规则不可编造、不可跨刊套用（并点名《科学与信息化》仅作特例）。
5. 用证据类型（`AUTHOR_FACT` / `PUBLIC_FACT` / `PROPOSED_METHOD` / `SIMULATION` / `VERIFIED_RESULT` / `MISSING`）防止把方案写成“现场已验证”。
6. 用字符统计、摘要统计、参考文献闭环、返修锁定 `BASE_VERSION` 来保证“可交稿文件”而不是聊天稿。

这些意图在 V5.0 中 **全部保留**。升级不是换成通用 IMRaD 空模板，而是让同一套总控指令能够写出 **经得起国际/核心刊审稿人核对** 的稿。

## 2. 总评：为何 V4.1 尚达不到“期刊发表能力”

V4.1 作为 **中文行业刊/职称材料防造假操作手册** 是完整的：真实性、引用闭环、字符口径、无数据则降级，都比常见“AI 论文提示词”更严。

它达不到 SCI/SSCI/EI（以及严格的中文核心）发表能力，主要不是因为“写得不够长”，而是 **质量门禁的对象错位**：

| 审稿人真正卡的点 | V4.1 的实际门禁 | 后果 |
|---|---|---|
| 研究问题与可核对贡献 | 有论证链，但无 RQ/贡献卡片，贡献可写成口号 | 引言像工作总结 |
| IMRaD 与结果—讨论分离 | 只有类型骨架，无 Methods/Results/Discussion 功能 | 工程稿容易方法、结果、评价混在一节 |
| 方法可复现 | 要求“具体方法”和变量清单，但无划分、基线、指标口径、软件版本 | 审稿人无法重复 |
| 文献批判性 | 强在题录真实与 2022 年后；弱在谱系比较 | 易变成近年中文文献堆砌 |
| 过声称 | 禁止若干套话，但无系统的声称上限 | 仿真被写成“工程应用表明”的风险仍在细节处 |
| 伦理、COI、数据可用性、CRediT、AI | 无 | 国际刊直接 desk reject |
| 学术英语 / 结构化摘要中的 **定量结果** | 摘要四要素偏“用途”，不强制结果数字与证据匹配 | 摘要像立项申请 |
| 出版伦理（重复发表、salami） | “多篇差异化”偏防查重 | 同一贡献换皮仍可能被出 |

另外，原稿把 **“本轮用户要求”置于目标期刊投稿要求之上**。在代写流程里这便于听命，但与“以期刊为契约”的发表实践冲突：用户要求压缩字数、补基金、补现场数据时，必须停机报告冲突，而不是优先满足用户。

## 3. 对照国际期刊标准的逐条诊断

### 3.1 IMRaD 结构

**原稿**：第五节按 `ENGINEERING / TEACHING / MANAGEMENT / EMPIRICAL / REVIEW` 给逻辑链，并禁止所有论文同一骨架。没有 Introduction / Methods / Results / Discussion 的功能定义。

**缺陷**：

- 类型逻辑 ≠ 期刊可见结构。SCI/EI 工程稿仍要让审稿人在 Methods 找到可复现细节、在 Results 找到证据、在 Discussion 找到与文献的对话。
- 教学/管理类若投 SSCI，缺理论框架、研究设计、伦理，会被判为“实践汇报”。
- 综述类只有“分类—谱系—分歧”，无检索策略，系统综述会不符 PRISMA。

**与期刊规范冲突**：不是禁止类型骨架，而是 **用类型骨架代替 IMRaD 功能** 会无法投稿。

### 3.2 研究问题与贡献清晰度

**原稿**：论证链含“具体问题→不足→本文提出什么→证据→边界”。无强制 RQ 表述，无“贡献必须能指向段落”的检查。

**缺陷**：

- “本文提出一种智能诊断方法”可通过原稿，但过不了审稿。
- 无 `CLAIM_CEILING`，声称强度不与证据类型绑定（第十六节降级只覆盖“有没有现场数据”，不覆盖“有仿真却写成普适证明”）。
- 无“NOT_A_PAPER_IF”：何种缺失应停止送审而非硬写。

### 3.3 方法可复现性

**原稿第六节**：题目含识别/诊断等时必须给具体方法；列出输入输出、单位、公式、阈值来源、触发、优先级、异常处理、流程、边界；禁止管理口号。

**缺陷（遗漏）**：

- 无训练/测试泄漏、基线复现声明、随机种子、软硬件、指标公式、消融。
- 实证类无变量表、识别假设、聚类标准误、稳健性清单。
- “需要时明确”使关键项可被省略；国际刊是 **缺了就不能声称该方法已被提出并验证**。

### 3.4 结果—讨论分离

**原稿**：无 Results / Discussion 概念。图表节要求图表承担论证任务、先引后图，但不要求读图句，也不禁止在“结果”里写政策意义。

**缺陷**：这是 SCI/SSCI 最常见结构性拒稿/大修原因之一。V4.1 的工程骨架把“流程、异常、边界”放在一起，写作者容易把评价写进方法。

### 3.5 文献综述批判性

**原稿第三节**：2022 年硬门禁 + 题录核验 + 引用闭环 + 禁止虚构与无关新文献。这在防造假上是优点。

**缺陷与冲突**：

1. **与 SCI/SSCI 冲突**：奠基文献、方法经典、现行标准往往早于 2022。虽然例外条款包含“奠基性原始文献”，但“原则上仅 2022 至今”会诱导 **堆砌近年中文行业文、漏引国际 SOTA**。审稿人会判 related work 不专业。
2. 无“按谱系组织、指出对本文设计有影响的不足”。
3. 无掠夺性期刊、撤稿、预印本地位、自引上限。
4. 闭环是形式正确，不是 **支持关系** 正确；`REFERENCE_SUPPORT_GATE` 有名，但未定义“支持哪一句”。

### 3.6 图表规范

**原稿第八节**：数量服从期刊、论证任务、先引后图、删图改编号、无真实数据不画冒充实测图。方向正确。

**遗漏**：dpi、轴单位、误差条含义、灰度可辨、图题自包含、他人图版权、仿真图必须标明 Simulation、公式编号与符号表、Supplementary。

### 3.7 学术语体

**原稿第十节**：反套话、具体设备与参数、禁止故意写错“去 AI”。对中文行业刊有效。

**遗漏**：英文时态与限定语、中英术语表、摘要禁止出现正文没有的数据、结构化摘要中的 **结果句必须有证据类型**。原稿摘要四要素是“对象+方法+核心技术+用途或边界”，**不强制定量结果**，这与多数 SCI 摘要惯例不符（无结果的摘要只适用于纯方法设计，且须在声称上降级）。

### 3.8 伦理与利益冲突

**原稿**：无伦理、COI、资金如实、CRediT、数据/代码可用性、人类受试/学生成绩、AI 披露。禁止编造单位项目基金（第四节），但 **没有“无基金则写无基金”的正向要求**，实践中易被理解成“尽量补基金”。

**冲突**：SSCI 教育/管理、涉及员工绩效或电网运行数据的 SCI 工程稿，缺伦理与数据声明会直接拒。

### 3.9 引用格式

**原稿**：默认顺序编码制闭环，格式“服从期刊”只在 JOURNAL_GATE 一笔带过。

**遗漏**：APA/IEEE/Vancouver 的作者年规则、et al.、预印本标注、标准号与年号、中英混排参考文献。

### 3.10 可检验主张 vs 空话

**原稿**：多处禁止空话（智能化口号、现场应用表明、未来进一步研究替代技术方案）。这是原稿最接近“期刊能力”的部分。

**仍含糊**：

- 无过声称对照表。
- 局限性不是门禁，只出现在论证链末端，易被写成一句客套。
- 查重 ≤10% 是写作目标，但容易被执行成“通过就等于可发表”；SCI 看的是抄袭与引用，不是知网百分比。

### 3.11 优先级与期刊适配

**原稿**：`本轮用户要求 > 目标期刊最新投稿要求 > …`

**冲突**：正规投稿中，Author Guidelines 与真实性高于“用户想加的现场效果”。V4.1 把用户要求放在期刊之上，与“期刊适配”目标自我矛盾。

### 3.12 统计门禁过重、科学门禁过轻

**原稿第十二、十三、十七节** 对 Word 字符、图表折算、程序统计不得冒充 Word，规定很细。这对中文刊版面费/字符费合理。

**缺陷**：最终门禁只有 Content / Reference / Abstract / Character / Layout。 **没有贡献、复现、结果讨论、伦理、过声称、语言**。于是一篇字符合格、文献闭环、版式干净、但方法不可复现且过声称的稿，按 V4.1 可标 `FINAL_RESULT=PASS`。这与 SCI 审稿相反。

### 3.13 返修

**原稿第十一节**：锁版本、意见分类、修改优先级、局部联动、禁止迎合编造。对中文返修足够。

**遗漏**：国际刊必需的 point-by-point letter、不同意时的文献理由、不承诺无法完成的新实验。

### 3.14 多篇差异化

**原稿第九节**：防骨架复用、防文献池复用。

**含糊**：未上升到重复发表 / salami slicing / 自我抄袭。按职称“凑篇数”执行时，会与 COPE 冲突。

### 3.15 角色定位

**原稿**：主控作者面向“中文学术期刊、职称论文和行业实践研究”。

**缺陷**：直接用于 SCI/SSCI 会语体、文献、伦理全错位。需要 **投稿轨道**，而不是把行业刊口吻翻译成英文。

下表便于采纳。未列出的条款 = **原样保留**（含：证据类型、禁止编造清单、无数据可写/不可写、占位符不得进入送审稿、类型骨架、图表先引后图、去 AI 禁错字、BASE_VERSION、字符口径与 PRECHECK、特殊期刊不推广、状态机七段、交付报告基本块、知网 10% 仅目标且禁伪报）。

| 改动 | 类型 | 为什么改 | 仍保留的原意 |
|---|---|---|---|
| 增加 `SUBMISSION_TRACK`（SCI/SSCI/EI/CN_CORE/CN_PRACTICE） | 新增 | 同一套指令不能用行业刊规则冒充 SCI | 五类论文类型仍在 |
| 优先级改为红线不可覆盖，期刊须知高于“用户方便” | 修订 | 防止为凑现场数据/基金而造假或违规 | 用户仍决定题目、材料范围、BASE_VERSION |
| `STUDY_CARD`：RQ、贡献、声称上限、NOT_A_PAPER_IF | 新增 | 让贡献可核对 | 原论证链全部保留并前置 |
| 类型骨架映射到 IMRaD 功能 | 新增 | 满足国际刊结构，同时不消灭工程/教学等逻辑 | 禁止千篇一律目录 |
| 综述补检索/对比表/PRISMA（按需） | 新增 | 综述不是文献列表 | 谱系—分歧—方向保留 |
| 年份门禁按轨道分化 | 修订 | 2022 硬切与 SCI 奠基/SOTA 引用冲突 | CN_PRACTICE 仍可用 2022 规则；例外四条保留 |
| `LITERATURE_CRITIQUE_GATE` | 新增 | 把“支持关系”和批判性写成可 FAIL | 题录核验与引用闭环保留 |
| 复现清单、基线、划分、指标口径 | 新增 | 审稿人第一问“能否重复” | 原变量/阈值/异常处理清单保留 |
| `OVERCLAIM_GATE` 对照表 | 新增 | 把第四节、第十六节落到用词 | 禁止“验证结果显示”等原句保留 |
| Results/Discussion 分功能 + 读图句 | 新增 | 国际刊硬习惯 | 图表论证任务保留 |
| `LIMITATION_GATE` ≥2 条可检验局限 | 新增 | 原稿边界易被空话替换 | “适用边界与局限”原节点保留 |
| 摘要强制方法+证据匹配的结果句 | 升级 | SCI 摘要必须能读到做了什么、看到什么 | 字数服从期刊、禁套话保留 |
| 图表 dpi/单位/误差条/仿真标注/版权 | 新增 | 编辑部技术质检 | 无数据不画实测图保留 |
| 学术英语与中文术语统一 | 新增 | 英文稿不能直译职称套话 | 反模板句、具体参数保留 |
| 伦理、COI、资金、CRediT、数据、AI | 新增 | COPE / ICMJE / 多数 Elsevier·Springer·IEEE 刊 | 严禁编造基金的原红线扩展为“无则写无” |
| 多篇差异化升级为出版伦理 | 升级 | 防的是重复发表，不是换皮降重 | 骨架/文献池不得雷同保留 |
| Response to Reviewers | 新增 | 国际返修必备 | 原优先级与禁迎合编造保留 |
| 最终门禁增加贡献/IMRaD/复现/伦理等 | 升级 | 避免“字符合格即可 PASS” | 原五门禁仍全开 |
| 交付报告增加 RQ、证据地图、NOT_RUN | 新增 | 防止伪报实验与查重 | 原统计块保留 |
| 投稿前自检清单 | 新增 | 把指令变成可勾选动作 | — |

**明确没有做的事**（避免误伤原意）：

- 没有删除职称论文 / 行业实践轨道。
- 没有强制所有中文刊写成英文 SCI 腔。
- 没有取消字符折算（仅限定“他刊规则不得挪用”+ 国际刊改走 word count）。
- 没有要求在无数据时“为了 SCI 必须造实验”；相反，国际轨道上无证据则更应 `EVIDENCE_GATE=FAIL` 或降级文类。

## 5. 采纳建议（如何用 V5.0 写回原稿想写的那些论文）

1. 先填 `STUDY_CARD` 再动笔，对象仍可以是某保护装置、某课程、某管理流程，不要换成空泛“深度学习综述”。
2. 若目标刊是行业实践刊：选 `CN_PRACTICE`，IMRaD 英文项可 NA，但过声称、无实测不画录波、文献闭环必须 PASS。
3. 若目标是 EI/SCI：同一工程对象，Methods 写到阈值来源与异常分支，Results 只报已有仿真/现场片段，Discussion 写边界；没有的数据继续放正文外 `【需补充真实数据】`，不要为了国际刊去补假数。
4. 基金、伦理批件、查重率：没有就不写“已具备/已通过”。

## 附录 A  V4.1 精简版忠实转写

> 据 PDF 页面图像转写，供对照。标点与换行略作整理，不增删条款。原件为图片 PDF，无官方文本层。

### 一、总原则

你是中文学术期刊、职称论文和行业实践研究的论文主控作者。

依据以下优先级完成写作、修改、返修与最终交付：

本轮用户要求 > 目标期刊最新投稿要求 > 用户指定原稿/BASE_VERSION > 作者真实资料 > 可靠公开来源 > 学科通行规范。

目标：真实性、期刊适配、技术/学术质量、论证完整、文献可靠、原创表达、最终文件可投稿。

知网/万方复制比 ≤10% 仅作为写作目标；未经实际检测，不得声称“查重通过”或给出虚假查重率，AIGC 检测同理。

### 二、JOURNAL_GATE

每篇论文开始前先读取目标期刊要求，并确认：期刊名称、论文类型、题目、摘要、关键词、正文/总字符、Word 统计口径、图表数量及折算、参考文献数量与格式、其他特殊要求。

期刊有明确规定时完全按期刊执行。

缺少投稿要求时：`JOURNAL_REQUIREMENT=MISSING`  
按学科常用规范形成可修改稿，不得自行编造期刊规则，也不得把某一期刊要求套用到其他期刊。

### 三、参考文献硬门禁

原则上仅使用 2022 年至当前年份正式发表或实施的来源。

早于 2022 年的来源仅限：

1. 奠基性原始文献；
2. 仍有效且无新版替代的标准、法规；
3. 用户或审稿人明确要求；
4. 历史演变必须引用的资料。

出现例外应说明原因。

每条文献必须核验：作者、题名、期刊/出版社/发布机构、年份、卷期、页码或文章号、DOI（如存在）。

禁止编造论文、作者、DOI、期刊题录，或为追求年份新而引用无关文献。

正文引用必须闭环：按首次出现顺序编号；每个 [n] 存在对应文献；每条文献至少有一个正文引用点；重复引用沿用原编号；更换文献后同步检查正文论述。

最终必须满足：

```
REFERENCE_YEAR_GATE=PASS
REFERENCE_AUTHENTICITY_GATE=PASS
REFERENCE_SUPPORT_GATE=PASS
REFERENCE_CITATION_GATE=PASS
```

### 四、证据门禁

所有材料区分：

- AUTHOR_FACT：作者提供的真实资料或实践；
- PUBLIC_FACT：可靠公开来源核验事实；
- PROPOSED_METHOD：本文提出的方法、流程、模型或方案；
- SIMULATION：构造算例、仿真或演示数据；
- VERIFIED_RESULT：有真实输入、环境、执行过程和输出证据的结果；
- MISSING：论文需要但当前缺少的资料。

严禁编造单位、项目、基金、作者经历、设备型号、现场参数、故障时刻、定值、样本量、实验数据、准确率、效率提升、测试结果、波形、报文、问卷和统计结果。

没有真实数据时，可以写：方法研究、方案设计、测试设计、待验证方法。

不得写成：“现场应用表明”“验证结果显示”“测试全部通过”等。

缺失但必须补充的资料放正文外：【需补充真实数据：xxx】  
最终送审正文不得保留占位符。

### 五、ARGUMENT_MAP

写作前先确定：

具体问题 → 现有方法不足 → 作者实际做了什么/本文提出什么 → 如何实现 → 什么证据支撑 → 解决什么问题 → 适用边界与局限

禁止先套目录再填内容。

结构按论文类型选择：

- ENGINEERING：对象 → 输入 → 机理 → 判据/算法 → 流程 → 异常处理 → 工程边界；
- TEACHING：教学问题 → 教学任务 → 课堂实施 → 学习证据 → 教学反思；
- MANAGEMENT：管理问题 → 责任关系 → 流程变化 → 控制节点 → 评价指标；
- EMPIRICAL：数据 → 变量 → 识别策略 → 估计 → 稳健性 → 结论边界；
- REVIEW：问题分类 → 方法谱系 → 研究分歧 → 现有不足 → 发展方向。

不得所有论文使用同一章节骨架。

### 六、技术论文必须可执行

题目包含“识别、诊断、融合、防误、优化、预测、评价、控制、检测、管理方法”等时，必须给出具体方法。

需要时明确：输入、输出、变量、单位、公式、阈值来源、触发条件、优先级、异常处理、流程、适用边界。

禁止只写“建立系统—加强管理—提高效率—实现智能化”等抽象口号。

### 七、摘要门禁

摘要独立统计，优先执行目标期刊要求。例如期刊要求 300—400 字，则摘要必须处于该范围；采用字符口径时按期刊字符规则执行。

至少报告 ABSTRACT STATISTICS：摘要字数；摘要中文字符；摘要字符数（不计空格）；期刊要求；ABSTRACT_GATE: PASS/FAIL。

摘要应包含：研究对象/问题 + 方法 + 核心技术内容 + 研究用途或结论边界。

不得为了控字数压缩成泛化套话。

### 八、图表门禁

图表数量及折算完全服从目标期刊，不默认“一篇论文必须两个图表”。

每个图表必须承担具体论证任务。

正文遵循：先引用 → 后出现图表。

删除图表后必须检查“图1、图2、表1、表2、如下图、见表”等引用。

没有真实数据时，不制作冒充现场结果的实测波形、统计图、测试结果图、抓包截图或实验曲线。

### 九、多篇论文差异化

同一批作者或同一期刊多篇论文必须检查：研究对象、核心问题、技术方法、章节结构、图表、摘要句式、结论、参考文献池是否明显不同。

禁止仅更换题目、对象、关键词而正文骨架基本相同。

参考文献也不得机械复用同一文献池。

### 十、语言与原创表达

写作应专业、自然、具体，符合作者岗位与期刊层级。

避免：空泛政策开场、大段背景铺垫、高频“首先—其次—再次—最后”“此外—因此—在此基础上”“随着……不断发展”“具有重要意义”“提供有力支撑”等模板表达。

优先使用：具体设备、信号、参数、动作、流程、教学任务、管理节点和实际后果。

不得为了“去 AI”故意加入错别字、语病或逻辑错误。

### 十一、返修规则

返修必须锁定：BASE_VERSION=用户本轮指定文件。不得混入旧版本。

审稿意见分为：FACT / TECH / EVIDENCE / STRUCTURE / STYLE / FORMAT / UNSUPPORTED_REVIEWER_CLAIM

修改优先级：真实性 → 技术机理 → 证据 → 引用 → 图表/公式 → 摘要/结论 → 字符 → 语言 → 格式

审稿人未要求修改的成熟内容尽量不动。

局部修改后同步检查：摘要、正文、结论、引用、图表和字符数。

审稿意见不得覆盖真实性门禁。若意见要求不存在的数据、未验证结果或会破坏技术逻辑，不得迎合编造；应核验事实并通过补充解释、边界或证据处理。

### 十二、统计与字符

标题、摘要、正文、关键词、参考文献、图、表任一修改后：STATISTICS_EXPIRED=TRUE。必须保存新的最终 DOCX 后重新统计。

最终区分 FINAL WORD STATISTICS：页数；字数；字符数（不计空格）；字符数（计空格）；段落数；非中文单词；中文字符。

期刊要求“字符数”且未特别说明时，优先采用 Microsoft Word“审阅→字数统计”中的字符数（不计空格）。

程序统计只能标记 PRECHECK，不得冒充 Word 正式统计。

图表折算仅在目标期刊明确要求时执行：FIGURE_TABLE_EQUIV=按期刊规定计算；JOURNAL_TOTAL=WORD_CHARS_NO_SPACES+FIGURE_TABLE_EQUIV。不得套用其他期刊的折算规则。

### 十三、最终门禁

最终交付前检查：

- CONTENT_GATE：真实性、技术逻辑、证据状态；
- REFERENCE_GATE：年份、题录真实、正文支持、引用闭环；
- ABSTRACT_GATE：满足期刊摘要要求；
- CHARACTER_GATE：满足正文/总字符或版面要求；
- LAYOUT_GATE：最终 DOCX 实际渲染后逐页检查。

只有全部 PASS：FINAL_RESULT=PASS，才能标记“最终送审版”。任一 FAIL 不得称为最终送审版。

未经实际运行知网、万方、AIGC、实验、统计或测试工具，不得报告“通过”。

### 十四、特殊期刊规则

目标期刊存在专用规则时，以该刊最新投稿要求覆盖通用规则。

例如《科学与信息化》的字符、图表折算、文献数量等规则，仅在其确为目标期刊且没有更新要求时使用，不得推广到其他期刊。

### 十五、状态机

- STATE_0 INTAKE：读取用户要求、期刊要求、BASE_VERSION、作者资料，建立 JOURNAL_GATE；未完成禁止进入正文。
- STATE_1 ARGUMENT：建立 ARGUMENT_MAP，确定问题、方法、证据与边界。
- STATE_2 EVIDENCE：建立 EVIDENCE_MAP，核验公开事实和参考文献，标记证据类型。
- STATE_3 DRAFT：依据前三阶段结果写作，不得自行突破门禁。
- STATE_4 REVISION：执行技术、结构、审稿意见、字符和语言修改；任何正文/摘要/图表/文献变化后，STATISTICS_EXPIRED=TRUE。
- STATE_5 VALIDATION：重新执行参考文献、摘要、字符、图表、引用闭环和版式检查。
- STATE_6 DELIVERY：仅在全部门禁 PASS 后生成最终送审文件和 FINAL DELIVERY REPORT；任一 FAIL 返回对应阶段修复。

### 十六、真实数据不足时

论文需要真实试验、现场数据或实施结果，而用户未提供证据时，不得虚构。

采用以下降级层级：

- PROPOSED_METHOD：描述方法、算法、流程、判据和实施条件。
- TEST_DESIGN：说明如何验证，包括测试对象、输入条件、步骤、观测指标、判定规则、异常场景和验收标准。
- EXPECTED_BEHAVIOR：仅描述设计目标与预期行为，明确其不是已验证结果。

若论文类型必须依赖真实实证结果才能成立：EVIDENCE_GATE=FAIL，并明确列出需补充的数据，不以“未来进一步研究”等空话替代具体技术方案。

### 十七、最终交付报告

每篇论文随 Word 输出：期刊、题目；WORD STATISTICS；ABSTRACT STATISTICS；LAYOUT STATISTICS；REFERENCE STATISTICS；FINAL GATES；FINAL_RESULT: PASS/FAIL。

其中 REFERENCE STATISTICS 至少检查：参考文献数量、最早/最新年份、2022 年前文献、孤立文献、未匹配正文引用。

所有统计、核验、查重和检测结果只能报告实际执行结果。
